# Java AI 个人学习与生活助手架构级 OOD 设计方案 v2

## 概述

本方案将应用设计为一个面向单个本地用户的 Java 命令行个人助手，核心目标是同时满足 8 个业务功能和实验 1 白盒测试要求。整体架构采用分层与按业务能力分包结合的方式：控制台交互层只负责输入输出编排，应用服务层负责用例流程，领域服务与领域对象承载业务规则，基础设施层封装 DeepSeek API、配置、时间和可选外部资源。

核心设计目标包括：

- 业务逻辑与控制台菜单解耦，使 JUnit 能直接测试服务和领域对象。
- AI 能力通过接口隔离，真实 DeepSeek 调用与 mock、stub、fake 可互换。
- 当前时间、编号生成、配置读取等外部状态通过可替换抽象注入，避免测试依赖真实环境。
- 每个核心功能拥有清晰的职责边界，同时通过汇总服务完成跨模块读取和统计。
- AI 结构化建议采用“草稿生成、草稿持有、确认或取消、导入”的独立状态流，避免模型输出直接污染本地数据。
- 对课程测试重点涉及的状态冲突、日程冲突、空统计和外部依赖失败给出稳定行为契约，保证测试预期可重复。

设计中不要求持久化，默认数据存放在内存仓储中。若后续扩展文件存储，只需新增仓储实现，不影响业务服务和单元测试边界。

## 模块划分

### `assistant.app`

应用入口与交互编排模块。该模块包含控制台菜单、输入解析、结果展示和启动装配逻辑。它依赖应用服务接口，不直接操作仓储集合，不直接调用 HTTP 客户端，也不承载业务判断。这样可以将课程演示入口与可测试业务核心分离。

### `assistant.common`

通用领域基础模块。该模块提供跨业务共用的值对象、枚举、结果类型和校验协作对象，例如业务编号、日期范围、日期时间范围、交易金额、统计金额、操作结果和通用错误分类。它位于依赖链底部，被各业务模块使用，但不反向依赖具体业务。

### `assistant.task`

任务待办模块。负责任务的创建、查看、修改、删除、状态切换、按状态筛选、按优先级筛选，以及向汇总模块暴露今日任务视图。该模块内部维护任务状态流转规则，不让外部模块直接修改任务状态。

### `assistant.schedule`

日程提醒模块。负责课程、会议、考试和个人安排的记录、按日期查询、基于明确日期时间范围的冲突识别，以及基于可控当前时间判断即将开始、进行中和已过期等状态。它通过时间提供者获取“当前时间”，保证状态判断可重复测试。

### `assistant.study`

学习计划模块。负责学习目标创建、日期范围校验、进度更新、逾期判断、完成数量统计，以及为 AI 拆解建议提供计划上下文。该模块只管理正式学习计划，不直接接收 AI 原始输出；AI 输出需要先进入草稿生命周期。

### `assistant.finance`

收支记录模块。负责收入和支出记录、按类别筛选、按日期范围筛选、收入总额、支出总额和结余统计。单笔交易金额与统计结果金额使用不同语义的值对象表达：交易金额必须大于零，统计金额允许零和负结余。该模块也是白盒测试重点，内部规则应集中在可单独测试的服务或统计对象中。

### `assistant.note`

个人笔记或日记模块。负责笔记的新增、查看、修改、删除、关键字查询、标签查询，以及为 AI 摘要提供笔记上下文。该模块只负责本地笔记管理，摘要生成由 AI 应用服务编排。

### `assistant.summary`

数据查询与汇总统计模块。该模块以只读方式协作任务、日程、学习计划、收支和笔记模块，生成今日摘要、本周学习计划统计、本月收支统计、笔记数量和标签分布，以及可供 AI 使用的本地上下文。它不拥有业务数据，也不绕过各模块的公开查询契约。

### `assistant.ai`

AI 能力模块。负责 DeepSeek Flash 请求构造、模型配置、提示词生成、响应转换、结构化建议解析、AI 错误转换、草稿生命周期管理和草稿导入编排。该模块通过 `AiClient` 之类的接口隔离真实 HTTP 调用，单元测试使用 fake client 模拟正常响应、超时、鉴权失败、限流、空响应和格式异常。

### `assistant.testability`

可测试性支撑模块。该模块包含可替换时钟、编号生成器、测试数据工厂、内存仓储装配和 fake AI 客户端等测试友好抽象。生产代码只依赖其中的接口或简单基础实现，测试代码可使用专门实现控制外部状态。

## 核心抽象

### 通用基础抽象

`EntityId` 是表示记录唯一标识的值对象，用于任务、日程、学习计划、收支记录、笔记和 AI 草稿。它的职责是消除“同名记录无法定位”的歧义，并让修改、删除和草稿确认都能基于稳定标识协作。用值对象而不是裸整数，是为了集中表达编号有效性和相等性语义。

`IdGenerator` 是生成唯一标识的接口。内存递增编号是默认实现，测试可以替换为可预测实现。它被各业务服务在创建记录或草稿时使用，但领域对象本身不负责生成编号。

`TimeProvider` 是当前日期和时间的接口抽象。日程状态、学习计划逾期、本周统计、本月统计、今日摘要都依赖它。使用接口而不是直接调用系统时间，是为了保证状态迁移和边界日期测试稳定。

`DateRange` 是表示日期区间的值对象，负责表达开始日期、结束日期及其合法关系。收支查询、学习计划周期、本周统计等模块通过它协作。它适合使用不可变类，避免区间在查询过程中被修改。

`DateTimeRange` 是表示日程开始和结束时间的值对象，负责表达分钟级时间段和区间边界语义。日程冲突与“进行中”状态都基于它判断。该设计采用左闭右开区间语义：当前时间等于开始时间视为进入日程，等于结束时间视为已结束；两个日程首尾相接不视为冲突。使用独立值对象可以避免日程模块把单个日期时间误用为时间段。

`TransactionAmount` 是表示单笔收支金额的值对象，封装大于零的交易输入约束和精确计算语义。收入和支出记录只能持有该类型，从而集中拒绝零金额和负金额。

`MoneyValue` 是表示统计金额的值对象，封装精确金额计算语义，但允许零值和负值。收入总额、支出总额和结余使用它表达，因此空统计可以返回零值，支出大于收入时也可以表达负结余。它与 `TransactionAmount` 分离，是为了区分“单笔交易合法性”和“统计结果表达能力”。

`OperationResult` 是应用服务对控制台层返回稳定结果的对象语义。它表达成功、失败错误分类和必要的业务载荷。使用结果对象可以让 JUnit 断言明确错误类型，而不依赖完整控制台文本。

`BusinessException` 及其错误分类枚举负责表达可预期的业务错误，例如字段为空、范围非法、记录不存在、状态冲突、AI 服务不可用。领域值对象创建失败可以抛出明确业务异常；面向控制台的应用服务入口应将其转换为 `OperationResult`。这样既保留 Java 中异常表达非法状态的能力，又保证外层用例契约稳定。

`Repository<T>` 是各业务仓储契约的设计基础，表示按标识保存、查找、删除和列出领域对象的能力。实际设计中可以为各模块定义更贴近业务的仓储接口，而不是让所有模块强行共享一个过宽接口。默认实现是内存仓储，后续文件仓储可作为基础设施扩展。

### 任务待办抽象

`TaskItem` 是任务领域实体，代表一条可被跟踪状态的待办事项。它负责维护任务自身的完成状态和可修改信息，并保护“已完成、未完成”之间的状态一致性。它与任务服务协作，由服务负责校验输入、查找实体和触发状态变化。

`TaskPriority` 是任务优先级枚举，用于限定优先级取值范围。使用枚举能使非法优先级在解析或校验阶段被集中拦截，避免业务逻辑中到处判断字符串。

`TaskStatus` 是任务完成状态枚举，用于表示未完成和已完成等状态。它适合用枚举，因为状态集合固定且不需要复杂继承层次。

`TaskService` 是任务应用服务，负责新增、修改、删除、筛选、标记完成和撤销完成等用例。它协作任务仓储、编号生成器和校验对象。重复完成或重复撤销被定义为状态冲突失败，服务返回稳定错误分类且不得修改状态；状态变化后的统计同步不由它主动推送，而是由汇总服务按当前仓储状态重新计算，降低模块耦合。

`TaskQuery` 是任务筛选条件对象，表达按状态、优先级或日期等条件查询的意图。它将控制台输入解析结果与业务查询逻辑分离，使筛选分支便于单元测试。

### 日程提醒抽象

`ScheduleItem` 是日程领域实体，表示课程、会议、考试或个人安排。它承担日程基本信息和 `DateTimeRange` 时间段语义，并为冲突识别提供可比较的边界。

`ScheduleStatus` 是日程状态枚举，表示即将开始、进行中和已过期等展示状态。状态由服务根据 `DateTimeRange` 和 `TimeProvider` 动态判断，而不是长期存储在实体中，这样可以避免时间变化后状态失真。

`ScheduleConflictPolicy` 是日程冲突判断策略。它负责定义什么样的时间重叠算冲突。本版基础策略采用确定规则：同一日期中两个 `DateTimeRange` 存在非空重叠即冲突，首尾相接不冲突。使用策略组件而不是把判断写死在服务中，有利于对白盒路径单独测试，也为未来差异化冲突规则保留扩展点。

`ScheduleService` 是日程应用服务，负责新增日程、按日期查询、识别冲突和计算展示状态。新增日程时若存在冲突，基础契约是拒绝保存并返回冲突错误分类，不采用“保存但警告”的二义行为。它协作仓储、冲突策略和时间提供者，不直接处理控制台输入格式。

### 学习计划抽象

`StudyPlan` 是学习计划领域实体，表示一个有时间范围、预期投入和进度状态的学习目标。它负责保护进度在合法范围内，并表达完成、未完成、逾期等领域语义。

`Progress` 是表示完成进度的值对象，封装 0% 到 100% 的合法边界。它适合用不可变值对象，避免服务层重复判断小于 0 或大于 100 的情况。

`StudyPlanStatus` 是根据进度、开始日期、截止日期和当前时间推导出的状态枚举或分类对象。未开始、进行中、已完成、未完成但逾期等状态可由领域服务统一判断。

`StudyPlanService` 是学习计划应用服务，负责创建计划、更新进度、统计完成与未完成数量、提供 AI 拆解上下文。它协作计划仓储、时间提供者和进度校验对象。

`StudyPlanAnalysisService` 是学习计划统计与状态分析组件，专门处理完成率、逾期判断、本周计划统计等规则。将统计规则拆出有利于对复杂分支进行基本路径测试。

### 收支记录抽象

`TransactionRecord` 是收支记录领域实体，表示一笔收入或支出。它承担交易金额、类别、日期和备注的业务语义，但不负责跨记录统计。它使用 `TransactionAmount` 表达单笔金额，确保交易记录不能出现零金额或负金额。

`TransactionType` 是收入和支出的枚举，限定收支方向。使用枚举能使未知类型在输入转换时被拒绝，也能让统计逻辑清晰区分收入总额和支出总额。

`TransactionQuery` 是收支查询条件对象，用于表达类别筛选、日期范围筛选和类型筛选。它与 `DateRange` 协作，保证开始日期晚于结束日期等错误在查询前被发现。

`FinanceService` 是收支应用服务，负责记录收入、记录支出、删除记录和执行查询。它不直接负责最终报表格式，而是返回可被统计服务或控制台层使用的业务结果。

`FinanceStatistics` 是收支统计结果对象，表示收入总额、支出总额和结余等汇总信息。它适合作为不可变值对象，便于测试断言和避免展示层误改统计结果。收入总额和支出总额允许为零，结余允许为零或负数，因此它使用 `MoneyValue` 而不是 `TransactionAmount`。

`FinanceStatisticsService` 是统计组件，负责从符合条件的交易记录中计算汇总。它适合成为白盒测试重点，因为金额累计、空集合、收入支出分类、日期边界和负结余都有明确路径。空集合统计稳定返回收入为零、支出为零、结余为零的统计对象。

### 笔记管理抽象

`Note` 是个人笔记领域实体，表示带标题、内容、创建日期和标签的文本记录。它负责维护笔记自身内容和标签集合的有效性。

`Tag` 是笔记标签值对象，统一处理空标签、大小写或前后空白等标签语义。是否进行大小写归一可作为实现细节，但设计上应由标签抽象集中处理。

`NoteQuery` 是笔记查询条件对象，用于表达关键字查询、标签查询或组合查询。关键字为空、无匹配和标签不存在等情况通过该对象及服务契约明确处理。

`NoteService` 是笔记应用服务，负责新增、查看、修改、删除、关键字查询和标签查询。它向 AI 模块提供指定笔记或查询结果的摘要上下文，但不直接调用 AI。

`NoteSearchPolicy` 是笔记匹配策略，负责定义关键字匹配标题、内容或标签的规则。将匹配规则抽出，可以让“关键字为空”“无匹配”“多字段匹配”等分支独立测试。

### 汇总统计抽象

`DashboardSummary` 是跨模块摘要结果对象，表示今日待办和日程、本周学习计划、本月收支、笔记数量和标签分布等汇总视图。它是只读数据传输对象，不拥有业务规则。

`LocalContext` 是供 AI 提示词使用的本地上下文对象。它来自真实业务数据，但被裁剪成适合模型输入的摘要结构。它的职责是隔离“业务对象内部结构”和“AI 提示词需要的上下文结构”。

`SummaryService` 是跨模块查询服务，按只读方式协作任务、日程、学习计划、收支和笔记服务。它负责组合当前数据并生成摘要，不直接修改任何模块数据。

`ContextProvider` 是 AI 模块获取本地上下文的接口。默认实现委托 `SummaryService`，测试实现可以返回空上下文、单模块上下文或多模块组合上下文，便于覆盖 AI 请求构造路径。

### AI 能力抽象

`AiClient` 是外部大模型调用契约，表达发送请求并获得响应的能力。业务代码只依赖该接口，不依赖 HTTP 细节。真实实现面向 DeepSeek OpenAI 兼容接口，测试实现模拟各种响应和异常。

`DeepSeekAiClient` 是 `AiClient` 的基础设施实现，负责使用 `https://api.deepseek.com` 和 `deepseek-v4-flash` 构造真实请求。它只处理协议、鉴权、超时和底层响应，不理解任务、计划或笔记业务规则。

`AiConfiguration` 是 AI 配置对象，表示 base_url、模型名称、API Key 来源和超时等配置。使用配置对象而不是硬编码，能够满足 API Key 不写入源码的要求，也便于测试断言模型和地址正确。

`PromptBuilder` 是提示词构造组件，负责将用户问题、场景类型和 `LocalContext` 组合成模型输入。它与业务服务只通过上下文对象协作，避免提示词逻辑散落在多个服务中。

`AiAssistantService` 是 AI 问答与建议应用服务，负责根据用户问题和本地上下文调用 AI、处理空响应和错误，并返回可展示的建议结果。AI 失败时，它应返回明确的降级错误结果，保证本地非 AI 功能仍可继续使用。

`StructuredSuggestionParser` 是结构化建议解析组件，负责把 AI 返回的任务拆解、学习计划草稿或自然语言解析结果转换为受控草稿内容。它不直接写入任务或学习计划仓储，也不决定草稿最终状态，而是只产生可验证的中间表示。

`SuggestionDraft` 是 AI 结构化建议的草稿聚合根。它表示一条被生成但尚未导入正式业务数据的建议，维护草稿类型、内容完整性和生命周期状态。使用独立草稿对象是为了清晰表达生成、可确认、已取消、已导入、重复确认和格式异常等状态路径。

`SuggestionDraftStatus` 是草稿生命周期状态枚举。基础状态包括可确认、已取消和已导入。格式异常的 AI 输出不会创建可确认草稿；导入失败不改变草稿的可确认状态，而是通过导入结果返回失败原因。这样可以保证“取消后不能确认”“导入后不能重复确认”“失败后正式数据不半写入”等路径可稳定测试。

`SuggestionDraftRepository` 是草稿持有和查询边界。它负责在内存中保存解析成功的草稿，并支持按草稿标识查找、列出待确认草稿和更新草稿状态。它不属于已删除的数据持久化功能，因为默认实现只保存本次运行中的临时草稿状态。

`DraftLifecycleService` 是草稿生命周期应用服务，负责创建可确认草稿、查询草稿、取消草稿和把确认命令转交给导入服务。控制台层通过草稿标识与它交互，因此连续生成多个草稿、稍后确认、取消后再次确认、重复确认等流程都有稳定服务边界。

`DraftImportService` 是草稿导入应用服务，负责在用户确认后将草稿转换为正式任务或学习计划。它协作目标业务服务完成校验和写入；当目标服务校验失败时，正式数据不得出现半写入状态，草稿保持可确认状态并返回可断言的失败原因。导入成功后草稿进入已导入状态，重复确认同一草稿返回状态冲突失败且不得重复新增正式记录。

`AiErrorMapper` 是 AI 错误转换组件，负责将超时、鉴权失败、限流、空响应和格式异常等外部错误转换为应用可理解的错误分类。这样控制台层可以显示一致的错误提示，单元测试也能断言稳定错误类型。

## 关键行为契约

### 应用启动与依赖装配

启动时，应用装配内存仓储、草稿内存仓储、递增编号生成器、系统时间提供者、AI 配置、真实或模拟 AI 客户端，以及各应用服务。控制台层只持有应用服务入口，不直接持有仓储实现。测试启动则可装配固定时间、固定编号和 fake AI 客户端。

### 任务待办管理

创建任务时，任务服务校验标题、优先级和截止日期等输入，生成唯一标识并保存任务实体。非法输入应被拒绝且不改变仓储状态。标记完成时，服务必须先确认任务存在，再根据当前状态执行状态迁移；如果任务已经完成，再次标记完成返回状态冲突失败，任务状态和统计依据不变。撤销完成同理，如果任务已经未完成，再次撤销返回状态冲突失败。

筛选任务时，服务根据查询条件返回当前仓储快照中的匹配任务。查询本身不得修改任务状态。汇总服务读取任务服务的只读查询结果来生成今日任务和任务完成统计。

### 日程提醒管理

创建日程时，日程服务校验名称、日期时间范围、地点和备注等输入，并通过冲突策略判断是否与已有日程冲突。结束时间必须晚于开始时间。若与已有日程存在非空重叠，服务拒绝保存并返回日程冲突错误分类；首尾相接的两个日程不视为冲突。该确定契约使冲突识别测试可以直接断言保存结果和仓储状态。

按日期查询时，服务返回该日期内开始或覆盖该日期的日程集合，并基于可控当前时间计算展示状态。当前时间早于开始时间时为即将开始；当前时间大于等于开始时间且小于结束时间时为进行中；当前时间大于等于结束时间时为已过期。测试应能通过固定 `TimeProvider` 覆盖边界时间。

### 学习计划管理

创建学习计划时，计划服务校验目标名称、开始日期、截止日期、预期投入和初始进度。截止日期早于开始日期时必须拒绝。更新进度时，进度值必须处于合法区间；进度达到 100% 后，计划状态应被识别为已完成。

计划状态由进度、日期范围和当前时间共同决定。未开始、进行中、已完成、未完成但逾期等状态应通过统一分析组件推导，避免不同服务给出不一致结论。AI 拆解建议只读取计划上下文，不直接修改计划。

### 收支记录管理

新增收支记录时，服务校验金额必须大于零、类型必须为收入或支出、日期必须合法。非法输入不改变记录集合。查询时，类别、类型和日期范围作为组合条件参与筛选；开始日期晚于结束日期必须在查询前拒绝。

统计时，统计组件对筛选后的记录分别累计收入和支出，并计算结余。空记录统计返回零值统计对象，而不是异常。只有支出没有收入时，结余返回负数统计金额。删除记录后，后续统计必须基于当前记录集合重新计算。

### 笔记管理与 AI 摘要

新增或修改笔记时，服务校验标题和内容非空，并处理标签语义。关键字查询应明确区分关键字为空和无匹配两种情况：关键字为空属于输入错误，无匹配则返回空结果集合。

AI 摘要由 AI 应用服务编排：笔记服务提供指定笔记或查询结果上下文，提示词构造组件生成摘要请求，AI 客户端返回结果，错误转换组件处理失败。AI 摘要失败不得影响笔记本地数据。

### 数据查询与汇总统计

汇总服务以只读方式读取各业务服务，生成今日摘要、本周计划统计、本月收支统计、笔记数量和标签分布。它必须基于当前内存数据即时计算，而不是维护一份容易过期的缓存。任务新增、删除、完成状态变化，收支新增或删除，学习计划进度更新，笔记新增或删除，都应在下一次汇总中体现。

生成 AI 本地上下文时，汇总服务应输出面向模型的摘要信息，而不是暴露所有领域对象细节。空数据、单模块数据和多模块组合数据都应有稳定表示，供 AI 请求构造测试断言。

### AI 问答与建议

AI 问答服务接收用户问题和场景类型后，通过上下文提供者获取本地摘要，使用提示词构造组件生成请求，再通过 `AiClient` 调用模型。请求契约必须包含正确的 base_url、模型名称、用户问题和必要本地上下文。AI 返回自然语言建议时，服务只保证展示结果和错误分类，不对完整自然语言文本做确定性承诺。

当 API Key 未配置、网络超时、鉴权失败、限流、空响应或响应格式异常时，AI 问答服务返回明确失败结果，不修改任何本地业务数据，并保持任务、日程、学习计划、收支和笔记等本地服务可继续工作。

### AI 结构化建议确认导入

结构化建议流程分为生成草稿、持有草稿、用户确认或取消、导入正式记录四个阶段。AI 原始输出必须先由解析组件转换为草稿内容；草稿字段缺失或格式异常时拒绝创建可确认草稿，并返回格式错误分类。

解析成功后，草稿生命周期服务生成草稿标识并保存到草稿仓储。用户后续通过草稿标识确认或取消，因此可以稳定支持多个草稿并存、稍后确认和重复操作测试。用户取消时，草稿进入已取消状态，本地正式数据不变化；已取消草稿再次确认返回状态冲突失败。

用户确认时，生命周期服务先检查草稿存在且处于可确认状态，再委托导入服务根据草稿类型调用任务服务或学习计划服务。目标服务仍执行完整业务校验，避免草稿绕过规则。导入成功后，导入服务将草稿更新为已导入；重复确认已导入草稿返回状态冲突失败，不得重复新增正式记录。导入失败时，正式数据保持原状，草稿仍处于可确认状态，返回目标服务校验失败或写入失败的稳定错误分类。

## 错误处理策略

错误分为四类：

- 输入校验错误：字段为空、格式非法、金额小于等于零、进度越界、日期区间非法、日期时间结束不晚于开始、未知枚举值等。这类错误应在值对象创建或应用服务校验阶段拒绝，并向控制台层返回明确错误分类。
- 业务状态错误：记录不存在、重复完成、重复撤销、日程时间冲突、重复确认草稿、已取消草稿再次导入、删除不存在记录、状态迁移不允许等。这类错误由业务服务判断，保证数据状态不被破坏。
- 外部依赖错误：DeepSeek 超时、鉴权失败、限流、网络不可用、空响应、格式异常、API Key 未配置等。这类错误由 AI 客户端和错误转换组件封装，不向业务服务泄露底层 HTTP 细节。
- 系统错误：不可预期的运行时异常。控制台层应统一兜底，避免程序崩溃，但这类错误不应替代可预期业务错误。

为了稳定白盒测试预期，应用服务对外采用统一的结果对象语义：成功时返回成功结果和必要业务载荷，失败时返回错误分类和状态不变保证。领域值对象可在创建非法值时抛出业务异常，但应用服务入口负责捕获并转换为结果对象。AI 服务也返回带错误分类的结果对象，因为 AI 失败属于常见外部状态，调用方需要展示降级提示并继续运行本地功能。

单元测试应断言稳定的错误分类、状态不变和必要提示语义，而不是断言控制台完整文本。

## 并发设计

本应用默认是单用户命令行程序，不要求支持多线程并发写入。业务服务可以按顺序处理用户命令，内存仓储只需满足单线程演示和单元测试需求。

AI 调用可以作为同步用例处理，以降低实验复杂度。如果后续希望避免命令行等待，可将 AI 请求放入异步执行器，但异步边界应限制在 AI 应用服务或基础设施层，不应让领域对象感知线程模型。

共享可变状态主要存在于内存仓储和草稿仓储中。设计上通过服务统一修改仓储，外部模块只获得只读结果或不可变快照。若后续引入异步 AI 或并发命令，应将仓储实现替换为线程安全版本，或在应用服务层增加同步策略；核心领域抽象不需要改变。

## 设计决策

### 采用业务分包而不是按技术层大包集中所有类

需求包含 8 个核心功能，每个功能都有独立状态、校验和测试关注点。按任务、日程、学习计划、收支、笔记、汇总、AI 分包，可以让职责边界与测试边界一致。通用基础类型放入 `assistant.common`，避免重复实现日期范围、日期时间范围、金额、编号和错误分类。

### 控制台 UI 与业务服务严格分离

课程实验重点是白盒测试，不是界面效果。若把判断逻辑写在 `main` 方法或菜单分支中，JUnit 难以直接覆盖。控制台层只负责编排输入输出，业务服务返回明确结果，使测试可以绕过控制台直接构造输入并断言状态。

### AI 客户端使用接口隔离真实 DeepSeek 调用

真实 API 调用不适合作为单元测试依赖。`AiClient` 将请求响应契约与 HTTP 实现分离，`DeepSeekAiClient` 只作为基础设施实现。这样单元测试可以用 fake client 覆盖正常响应、超时、鉴权失败、限流、空响应和格式异常，同时组件或集成测试仍能单独验证 `https://api.deepseek.com` 和 `deepseek-v4-flash` 配置。

### AI 建议采用可持有草稿生命周期而不是临时变量或直接写入业务数据

需求明确要求 AI 结构化建议必须先确认再导入。独立的 `SuggestionDraft`、`SuggestionDraftRepository` 和 `DraftLifecycleService` 能表达生成、查询、可确认、已取消、已导入、导入失败和重复操作等状态。草稿状态不应只存放在控制台临时变量中，否则无法支持多草稿并存和服务层状态迁移测试。导入服务复用目标服务的业务校验，可以保证草稿与手工输入遵守同一规则。

### 日程使用日期时间范围并固定边界语义

需求要求识别同一时间段冲突和进行中状态，因此单个日期时间不足以支撑设计。`DateTimeRange` 将开始、结束和左闭右开边界集中起来，冲突策略使用非空重叠作为基础规则。这样 10:00-11:00 与 11:00-12:00 不冲突，10:00-11:00 与 10:30-11:30 冲突，状态判断也能在开始和结束边界上稳定断言。

### 区分交易金额和统计金额

单笔收支记录必须拒绝零金额和负金额，但统计结果必须表达空集合零值和负结余。将 `TransactionAmount` 与 `MoneyValue` 分离，可以同时满足输入校验和统计表达需求，避免用一个“正金额”值对象承载所有金额语义造成约束冲突。

### 汇总服务采用即时只读计算而不是维护冗余缓存

任务状态、学习计划进度、收支记录和笔记数量都会频繁变化。若维护独立统计缓存，删除或状态变化后容易出现同步缺陷。汇总服务每次从各业务服务读取当前数据并计算摘要，逻辑更直接，也便于通过单元测试验证跨模块状态同步。

### 使用值对象集中边界规则

金额、进度、日期范围、日期时间范围、编号、标签等规则如果分散在各服务中，会导致重复判断和测试遗漏。使用不可变值对象集中表达合法性和语义，有利于单元测试覆盖边界值，也使服务层更关注用例流程。

### 状态采用枚举或推导对象，避免字符串状态

任务状态、日程状态、学习计划状态、草稿状态、收支类型和优先级都适合用 Java enum 表示或推导。这样能利用 Java 类型系统限制非法取值，并让分支覆盖更明确。对需要随时间变化的状态，如日程和计划状态，设计上由服务动态推导，避免长期存储过期状态。

### 当前时间和编号生成器可替换

日程状态、逾期判断、今日摘要、本周统计、本月统计和草稿标识都依赖外部状态。直接使用系统时间或不可控编号会导致测试不稳定。通过 `TimeProvider` 注入当前时间，通过 `IdGenerator` 注入编号生成，测试可以固定边界点并预测创建结果。

### 仓储接口保持业务语义，不提前引入数据库或文件持久化

本版需求删除数据持久化与导出，因此内存仓储足够满足实验范围。设计保留仓储接口，是为了隔离数据访问和业务逻辑，而不是引入不必要的复杂基础设施。草稿仓储也是运行期内存状态持有边界，不等同于用户数据持久化。未来如扩展文件 I/O，可新增实现并将真实 I/O 测试归入组件或集成测试。

## 白盒测试友好性设计

本设计支持将以下对象作为重点白盒测试目标：

- `FinanceStatisticsService`：覆盖金额累计、收入支出分类、空集合、日期范围边界、零值统计和负结余。
- `DraftLifecycleService` 与 `DraftImportService`：覆盖草稿生成后查询、取消、确认、重复确认、取消后确认、目标服务校验失败和回滚。
- `SummaryService`：覆盖无数据、单模块数据、多模块数据、数据变化后的统计同步。
- `ScheduleService` 与 `ScheduleConflictPolicy`：覆盖冲突识别、首尾相接、非空重叠、按日期查询和基于固定时间的状态判断。
- `StudyPlanAnalysisService`：覆盖 0%、100%、越界进度、未开始、进行中、完成和逾期路径。
- `AiAssistantService` 与 `PromptBuilder`：覆盖模型配置、本地上下文包含、空响应、超时、鉴权失败、限流和格式异常。

测试装配应使用内存仓储、草稿内存仓储、固定时间提供者、可预测编号生成器和 fake AI 客户端。每个测试通过重新创建服务和仓储隔离状态。真实 DeepSeek 连通性、网络超时配置和 API Key 验证只作为组件或集成测试单独执行，不纳入普通 JUnit 单元测试依赖。

## 模块依赖方向

依赖方向从外向内为：

`assistant.app` 依赖各应用服务；各应用服务依赖领域对象、仓储契约、通用值对象和必要的外部接口；基础设施实现依赖外部协议或环境配置，并实现应用层声明的接口；领域对象不依赖控制台、HTTP、文件系统或测试工具。

跨业务读取统一通过服务或查询接口完成。任务、日程、学习计划、收支和笔记模块之间不直接互相修改数据。汇总模块只读协作多个模块；AI 模块通过上下文提供者读取汇总结果，并通过草稿生命周期服务和草稿导入服务在用户确认后调用目标业务服务。
