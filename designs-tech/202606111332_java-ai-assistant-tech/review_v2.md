# 技术方案审查报告（v2）

## 审查结果

APPROVED

## 逐维度审查

### 1. 技术准确性

**[通过]** DeepSeek 接入决策与当前官方文档一致：OpenAI 兼容 base URL 为 `https://api.deepseek.com`，Chat API 路径为 `/chat/completions`，模型列表包含 `deepseek-v4-flash`，请求采用 Bearer API Key、`messages` 和非流式参数的路径可落地。

**[通过]** Java 17、JDK `java.net.http.HttpClient`、Jackson Databind、JUnit Jupiter、Mockito、JaCoCo、Maven Surefire 和 Maven Failsafe 均是存在且适用于本项目规模的技术选型。Maven Central 元数据确认 `maven-surefire-plugin:3.5.6`、`maven-failsafe-plugin:3.5.6`、`junit-jupiter:5.14.4`、`mockito-core:5.18.0`、`jackson-databind:2.19.0` 和 `jacoco-maven-plugin:0.8.13` 均可解析；v1 中 Surefire `3.6.0` 不存在的问题已修正。

**[通过]** 方案中的 Java 类型系统使用方式在 Java 17 能力范围内：实体使用 class，值对象和只读 DTO 可使用 record，状态使用 enum，服务依赖接口和内存实现，均不存在语言能力越界。

**[通过]** 数据方案与需求边界一致。本版需求删除用户数据持久化与导出，技术方案明确使用进程内内存仓储，AI 草稿仅作为运行期内存状态，不把它误定义为用户数据持久化。

### 2. 完备性

**[通过]** 需求中的 8 个核心功能均有对应技术路径：AI 问答与本地上下文、AI 结构化建议草稿确认导入、任务、日程、学习计划、收支、笔记、跨模块汇总统计都已有服务、仓储、状态和错误处理方案。

**[通过]** 构建、目录、依赖、DeepSeek 配置、API Key 管理、超时、HTTP 状态映射、JSON 解析、内存仓储、测试分层、覆盖率证据和交付物组织均已覆盖，满足任务描述要求的技术方案边界。

**[通过]** 数据流闭环清晰。用户输入经控制台层进入服务和值对象校验，业务数据写入内存仓储，查询和汇总通过只读服务返回；AI 问答通过本地上下文、提示词、客户端、响应解析和错误映射形成闭环；结构化建议通过解析、草稿、确认或取消、导入和回滚形成闭环。

**[通过]** 测试技术路线覆盖实验 1 的重点要求，明确普通单元测试隔离真实 DeepSeek、真实网络和真实日期，真实 API 验证放入集成测试 profile，JaCoCo 覆盖率和白盒路径映射也有明确交付位置。

### 3. 可操作性

**[通过]** 技术选型和版本号均给出明确结论，未留下需要实现者自行探索的核心方向性问题。实现者可以直接按 Java 17、Maven 单模块、指定依赖版本和包结构启动编码。

**[通过]** 关键业务规则均有可编码的大方向：任务重复完成返回状态冲突，日程冲突按左闭右开非空重叠判断，学习计划状态由统一分析服务推导，金额区分交易金额和统计金额，笔记搜索策略集中处理，汇总服务即时只读计算。

**[通过]** AI 结构化建议的可操作路径明确：限定草稿类型、Jackson `JsonNode` 解析、支持 fenced JSON、字段和枚举校验、草稿生命周期状态、确认导入复用目标服务校验、失败回滚和重复确认错误分类均已定义。

**[通过]** 实施顺序合理，先搭建构建与可测试业务核心，再实现汇总、AI、结构化建议、控制台和实验材料，能够降低外部 API 和界面层对单元测试开发的阻塞。
