# 技术方案审查报告（v1）

REJECTED

## 逐维度审查

### 1. 技术准确性

**[通过]** DeepSeek API 接入方案与官方文档一致：OpenAI 兼容 base URL 使用 `https://api.deepseek.com`，聊天接口路径为 `/chat/completions`，模型列表包含 `deepseek-v4-flash`，请求头使用 Bearer API Key，请求体包含 `model`、`messages` 和非流式参数。

**[通过]** Java 17、JDK `java.net.http.HttpClient`、Jackson Databind、JUnit Jupiter、Mockito、JaCoCo 与本项目场景匹配。`HttpClient` 支持客户端构建、连接超时、同步 `send` 和异步 `sendAsync`；Jackson 可用于 JSON 序列化和 `JsonNode` 解析；JUnit/Mockito/JaCoCo 能支撑单元测试、测试替身和覆盖率证据。

**[严重]** 技术方案固定使用 Maven Surefire `3.6.0`，该版本在 Maven Central 当前元数据中不存在；当前可解析版本包括 `3.5.6` 和 `3.6.0-M1`，没有正式 `3.6.0`。若实现者按方案配置 `maven-surefire-plugin:3.6.0`，`mvn clean test` 会因插件解析失败而无法运行，直接阻塞需求中的单元测试和提交验收路径。若集成测试的 Failsafe 也沿用同样版本号，同样会产生解析失败风险。

### 2. 完备性

**[通过]** 方案覆盖需求中的 8 个核心功能：AI 问答与建议、AI 结构化建议确认导入、任务待办、日程提醒、学习计划、收支记录、笔记管理、数据查询与汇总统计。

**[通过]** 方案明确排除了账号、多用户、数据库、文件导出、真实系统通知、健康管理、联系人管理和用户数据持久化，与需求 v4 删除 3 个模块后的范围一致。

**[通过]** DeepSeek API 接入、配置管理、错误映射、AI 草稿生命周期、导入回滚、内存仓储、时间和编号可替换、测试分层、覆盖率证据和交付物组织均有对应技术方案，数据流从控制台输入、业务服务、AI 客户端或内存仓储到输出结果形成闭环。

### 3. 可操作性

**[通过]** 包结构、目录结构、Maven 单模块工程、核心值对象、服务边界、仓储实现、AI 客户端边界和测试路线均给出明确结论，实现者能据此拆分编码任务。

**[通过]** 关键行为契约清晰：日程左闭右开区间、任务重复完成返回状态冲突、AI 草稿确认或取消、导入失败回滚、收支金额精度、空统计零值、本地功能不受 AI 失败影响等均可直接转化为单元测试预期。

**[一般]** 构建与测试运行路径中存在不可解析插件版本后，方案给出的 `mvn clean test`、`mvn clean verify`、`mvn -Pintegration verify` 路径无法被实现者稳定执行。该问题虽然修正范围小，但会影响实现者按方案启动项目、运行测试和生成实验 1 证据。

## 修改要求

- **问题**：将 Maven Surefire `3.6.0` 改为 Maven Central 可解析版本，并明确 Failsafe 插件版本也使用可解析版本。
- **原因**：需求要求提交可重复运行的 JUnit 单元测试脚本，方案也要求 `mvn clean test` 在无 API Key、无网络依赖的普通测试环境下可运行。不可解析插件版本会在构建阶段失败，阻塞编码和测试启动。
- **建议方向**：将 Surefire/Failsafe 版本统一改为已发布的 `3.5.6`，或明确采用里程碑版本 `3.6.0-M1`；若采用里程碑版本，应在方案中说明选择原因。推荐使用稳定已发布版本以降低课程环境构建风险。
