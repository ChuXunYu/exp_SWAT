# 详细设计（v29）

## 概述

本轮设计目标是补齐 Java AI Assistant 实验 1 测试交付文档，使项目除源码、单元测试和构建配置外，也具备课程验收需要的测试计划、白盒测试用例、覆盖证据说明、缺陷修复与回归记录、测试运行边界说明。

本轮实现范围：

- 新建 `java-ai-assistant/docs/test-plan.md`，记录测试目标、范围、环境、工具、分层、策略、运行命令和集成测试边界。
- 新建 `java-ai-assistant/docs/test-cases.md`，记录面向 8 个核心功能的代表性白盒测试用例、测试方法、被测类/方法、输入、预期结果、实际结果和通过状态。
- 新建 `java-ai-assistant/docs/defect-regression.md`，记录已发现缺陷、触发输入、修复方式、复现用例、重跑范围、回归结论和最终结果分析。
- 新建 `java-ai-assistant/docs/coverage/README.md`，记录 JaCoCo 报告生成方式，并选择 3 个复杂核心方法给出文字化控制流、圈复杂度、独立路径和测试用例映射。
- 更新 `java-ai-assistant/README.md`，增加测试交付文档索引、覆盖率报告生成命令和集成测试边界说明。
- 更新 `java-ai-assistant/docs/environment.md`，补充测试文档、JaCoCo 输出目录、默认单元测试隔离原则和当前无真实 DeepSeek 集成测试脚本的事实。

本轮不修改：

- `java-ai-assistant/pom.xml`。
- `java-ai-assistant/src/main/java/**` 下任何生产代码。
- `java-ai-assistant/src/test/java/**` 下任何测试代码。
- AI、任务、日程、学习计划、收支、笔记、汇总、控制台等服务公开契约。
- Surefire、Failsafe、JaCoCo、JUnit、Mockito 版本与插件行为。

文档必须基于当前工程事实编写：

- Maven 工程位于 `java-ai-assistant/`。
- Java 版本为 17。
- JUnit Jupiter 版本为 5.14.4。
- Mockito 版本为 5.18.0。
- Surefire/Failsafe 版本为 3.5.6。
- JaCoCo Maven Plugin 版本为 0.8.13。
- v28 验证报告记录 `mvn clean test` 通过 944 个测试，失败 0 个。
- 当前 `src/test/java` 下不存在 `*IT.java` 集成测试类。
- 普通单元测试不得访问真实 DeepSeek、真实网络、真实 API Key、真实用户文件或真实当前时间。

## 类型定义

### `docs/test-plan.md`

**形态**：Markdown 文档

**包路径**：不适用，文件路径为 `java-ai-assistant/docs/test-plan.md`

**职责**：作为实验 1 测试计划，说明如何围绕 8 个核心功能执行白盒单元测试、覆盖率收集、回归测试和可选集成测试。

**必须包含的章节**：

| 章节标题 | 内容契约 |
|----------|----------|
| `# 实验 1 测试计划` | 文档标题。 |
| `## 测试目标` | 至少包含业务正确性、异常输入、分支/条件/路径覆盖、状态迁移、跨模块同步、AI 外部依赖隔离、缺陷发现与回归验证。 |
| `## 测试范围` | 覆盖 8 个核心功能；明确不覆盖健康、联系人、数据持久化/导出；说明控制台层只作为交互入口补充测试，不是白盒覆盖核心。 |
| `## 测试环境` | 列出 Java 17、Maven、JUnit Jupiter 5.14.4、Mockito 5.18.0、Surefire 3.5.6、Failsafe 3.5.6、JaCoCo 0.8.13；操作系统可写为开发机环境不限，命令以 Maven 为准。 |
| `## 测试工具` | 说明 JUnit Jupiter、Mockito、Maven Surefire、Maven Failsafe、JaCoCo 的用途。 |
| `## 测试分层` | 区分单元测试、控制台交互单元测试、可选集成测试；明确普通单元测试不访问真实 DeepSeek、网络、API Key、用户文件或真实当前时间。 |
| `## 测试策略` | 至少覆盖语句覆盖、判定覆盖、条件覆盖、基本路径测试；结合边界值、等价类、错误推测、状态迁移和场景链路。 |
| `## 核心功能覆盖计划` | 用表格列出 8 个核心功能、主要被测类、代表性测试类、覆盖重点。 |
| `## 运行命令` | 包含 `mvn clean test`、`mvn clean verify`、`mvn jacoco:report`、`mvn -Pintegration verify`；说明命令从 `java-ai-assistant/` 目录执行。 |
| `## 集成测试边界` | 说明当前工程没有 `*IT.java`；真实 DeepSeek 连通性只作为可选未来集成测试，需要网络与 `DEEPSEEK_API_KEY`。 |
| `## 通过准则` | 至少包含默认单元测试全部通过、失败数为 0、无真实外部依赖、覆盖证据可追溯到用例和缺陷回归结论明确。 |

**数据契约**：

- `核心功能覆盖计划` 表格列必须包含 `核心功能`、`主要被测类`、`代表性测试类`、`覆盖重点`。
- 8 个核心功能名称必须与任务文件一致：
  1. AI 问答与学习生活建议。
  2. AI 结构化建议确认导入。
  3. 任务待办管理。
  4. 日程提醒管理。
  5. 学习计划管理。
  6. 收支记录管理。
  7. 个人笔记或日记管理。
  8. 数据查询与汇总统计。
- 运行结果引用应写明来源为 v28 验证报告：`mvn clean test` 通过 944 个测试、失败 0 个。不得伪造新的执行时间、覆盖率百分比或集成测试通过结果。

**构造方式**：

- 由编码步骤直接新建 Markdown 文件。

**类型关系**：

- 引用 `pom.xml` 中的 Maven 插件版本。
- 引用 `src/test/java/assistant/**` 下现有测试类。
- 与 `docs/test-cases.md`、`docs/coverage/README.md`、`docs/defect-regression.md` 互相链接。

### `docs/test-cases.md`

**形态**：Markdown 文档

**包路径**：不适用，文件路径为 `java-ai-assistant/docs/test-cases.md`

**职责**：作为白盒测试用例表，映射现有 JUnit 测试类和代表性测试方法，证明每个核心功能至少覆盖成功路径、典型失败路径、边界输入和状态变化。

**必须包含的章节**：

| 章节标题 | 内容契约 |
|----------|----------|
| `# 白盒测试用例` | 文档标题。 |
| `## 用例编号规则` | 说明编号格式，例如 `AI-01`、`DRAFT-01`、`TASK-01`、`SCHEDULE-01`、`STUDY-01`、`FINANCE-01`、`NOTE-01`、`SUMMARY-01`、`CONSOLE-01`。 |
| `## 测试方法说明` | 说明语句覆盖、判定覆盖、条件覆盖、基本路径、边界值、等价类、错误推测、状态迁移和场景链路在本项目中的用法。 |
| `## 用例总览` | 按 8 个核心功能分组列出代表性用例。 |
| `## 跨模块场景链路` | 至少列出 AI 草稿确认导入影响任务/学习计划、任务/日程/计划/收支/笔记变化后汇总同步等链路。 |
| `## 执行结果摘要` | 写明 v28 `mvn clean test` 通过 944 个测试、失败 0 个；实际结果列可以统一记录“通过”。 |

**用例表字段**：

每个核心功能分组表格必须包含以下列：

| 列名 | 说明 |
|------|------|
| `编号` | 稳定用例编号。 |
| `测试层级` | 例如单元测试、控制台交互单元测试、服务层场景测试。 |
| `测试方法` | 白盒方法或补充方法，例如判定覆盖、条件覆盖、基本路径、边界值、状态迁移。 |
| `被测类/方法` | 当前工程真实类名和方法名；方法名可按服务公开方法或测试目标描述填写。 |
| `JUnit 测试类/方法` | 当前工程真实测试类名；测试方法名必须尽量使用现有方法名，不确定的只写测试类名与覆盖场景，不得编造不存在的 `*IT`。 |
| `输入或前置条件` | 具体数据，例如金额、日期、进度、AI mock 响应、草稿状态、固定时间。 |
| `预期结果` | 具体断言，例如错误码、返回数量、状态不变、统计金额、草稿状态。 |
| `实际结果` | 对已执行单元测试写 `通过`；不得记录未执行的真实 DeepSeek 结果。 |

**最小用例覆盖要求**：

- AI 问答与学习生活建议：至少覆盖请求构造成功、base URL/model 配置、提示词包含本地上下文、空响应、超时/网络/鉴权/限流/格式异常映射。
- AI 结构化建议确认导入：至少覆盖任务草稿解析、学习计划草稿解析、字段缺失拒绝、确认导入、取消、本地数据不变化、重复确认冲突、导入失败回滚。
- 任务待办管理：至少覆盖新增成功、标题为空、状态筛选、优先级筛选、完成/重复完成/撤销完成、删除不存在、状态变化后汇总同步。
- 日程提醒管理：至少覆盖创建成功、名称为空、时间范围非法、冲突识别、首尾相接不冲突、按日期查询、即将开始/进行中/已过期状态。
- 学习计划管理：至少覆盖创建成功、日期范围非法、进度 0/100/-1/101、未开始/进行中/完成/逾期状态、统计。
- 收支记录管理：至少覆盖收入、支出、金额 0、负金额、两位小数边界、类别筛选、日期范围筛选、开始晚于结束、空集合统计、多笔统计、删除后统计。
- 个人笔记或日记管理：至少覆盖新增成功、标题为空、内容为空、关键字匹配、无匹配、空关键字、标签查询、修改/删除不存在。
- 数据查询与汇总统计：至少覆盖空数据、单模块数据、多模块组合、本周学习、本月收支、笔记标签、AI 本地上下文。

**构造方式**：

- 由编码步骤直接新建 Markdown 文件。

**类型关系**：

- 引用 `src/test/java/assistant/**` 下现有测试类。
- 与 `docs/test-plan.md` 的测试策略和 `docs/coverage/README.md` 的路径映射保持一致。

### `docs/defect-regression.md`

**形态**：Markdown 文档

**包路径**：不适用，文件路径为 `java-ai-assistant/docs/defect-regression.md`

**职责**：记录实现迭代中发现并修复的缺陷或可测性问题，证明每次修复都有复现测试、影响范围重跑和回归结论。

**必须包含的章节**：

| 章节标题 | 内容契约 |
|----------|----------|
| `# 缺陷修复与回归测试记录` | 文档标题。 |
| `## 记录口径` | 说明记录来自开发迭代和 JUnit 回归结果，最终以 v28 `mvn clean test` 944/0 为基准。 |
| `## 缺陷记录` | 用表格记录具体缺陷。 |
| `## 核心回归测试集` | 列出任务状态、日程状态、学习计划进度、收支统计、汇总、AI 失败降级、AI 草稿确认/取消等回归范围。 |
| `## 回归执行结论` | 写明默认单元测试通过，真实 DeepSeek 集成测试未作为默认回归执行。 |
| `## 残余风险` | 说明真实 DeepSeek 连通性依赖网络与 API Key，当前没有 `*IT.java`，覆盖率百分比需由本地 `mvn clean verify` 或 `mvn jacoco:report` 生成。 |

**缺陷记录表字段**：

| 列名 | 说明 |
|------|------|
| `编号` | 例如 `BUG-01`。 |
| `缺陷表现` | 用户可观察或测试可断言的问题。 |
| `触发输入/前置状态` | 具体输入或状态。 |
| `预期结果` | 应有行为。 |
| `实际结果` | 修复前行为。 |
| `可能原因` | 设计或实现层面的原因。 |
| `修复方式` | 已采取的修改措施。 |
| `复现/回归用例` | 对应测试类/测试方法或测试范围。 |
| `重跑范围` | 受影响测试包或全量 `mvn clean test`。 |
| `结论` | 通过或已修复。 |

**可记录的缺陷来源**：

文档可基于已完成迭代的真实修复主题进行归纳，包括但不限于：

- AI 配置与 DeepSeek 客户端错误映射边界。
- AI 结构化建议解析字段缺失或格式异常处理。
- AI 草稿确认导入状态冲突、取消后不写入本地数据、导入失败回滚。
- 控制台 AI 草稿入口由一次性列表改为循环子菜单，且列表不得截断前 10 条。
- 草稿 id 非正整数、非数字、小数、超出 `long` 范围时不得调用生命周期服务。
- 任务、日程、学习计划、收支、笔记、汇总中的边界输入和状态变化问题。

**事实约束**：

- 不得虚构真实 DeepSeek 缺陷已经通过网络复测。
- 不得虚构未运行的集成测试结果。
- 可以将“当前无 `*IT.java`”记录为残余风险或边界说明。

**构造方式**：

- 由编码步骤直接新建 Markdown 文件。

**类型关系**：

- 引用 `docs/test-cases.md` 中的用例编号。
- 引用 v28 验证报告中的全量单元测试执行结果。

**职责**：作为覆盖证据说明入口，说明 JaCoCo 报告如何生成，并对复杂核心方法提供白盒路径级证据。

|----------|----------|

| `## 重点方法路径分析` | 至少选择 3 个复杂核心方法。 |

**重点方法选择**：

必须从当前工程真实类型中选择 3 个方法，建议固定为：

| 方法 | 分析重点 |
|------|----------|
| `assistant.finance.FinanceStatisticsService.calculate(List<TransactionRecord>)` 或当前实际统计入口 | 空集合、收入累计、支出累计、收入支出混合、结余为负。 |
| `assistant.ai.DraftImportService.importDraft(SuggestionDraft)` 或当前实际导入入口 | 草稿类型分支、任务批量先校验后写入、学习计划导入、目标服务校验失败、回滚。 |
| `assistant.summary.SummaryService.createDashboardSummary()` 或当前实际摘要入口 | 空数据、单模块数据、多模块组合、当前日期/本周/本月范围、统计同步。 |

编码步骤应在写文档前核对实际方法名；如方法名不同，以当前源码真实公开方法为准，但仍保持上述分析对象。

**每个重点方法必须包含**：

- 被测方法全限定名。
- 文字化控制流步骤。
- 圈复杂度估算值，允许用“按主要判定节点估算”为口径。
- 独立路径列表。
- 独立路径到 JUnit 测试类/方法或用例编号的映射。
- 覆盖结论。

**事实约束**：

- 不得写具体 JaCoCo 百分比，除非编码步骤实际运行并获得报告；本轮设计不要求运行命令。
- 不得提交 `target/site/jacoco/**` 生成文件。
- 不得把覆盖率数字替代路径和用例映射。

**构造方式**：

- 由编码步骤创建 `java-ai-assistant/docs/coverage/` 目录并新建 `README.md`。

**类型关系**：

- 与 `pom.xml` 中 JaCoCo 插件配置一致。

## 错误处理

- 文档目录不存在：编码步骤应创建 `java-ai-assistant/docs/coverage/`，不得创建到项目根目录之外。
- 现有 `README.md` 或 `docs/environment.md` 内容与新增文档重复：以保留现有说明并追加索引/边界为主，不删除 DeepSeek 配置和测试隔离说明。
- 无 `*IT.java`：文档必须明确当前没有真实集成测试脚本，不得把 `mvn -Pintegration verify` 描述为已经验证 DeepSeek 连通性。
- 未实际运行 JaCoCo：覆盖文档只能说明生成方式和路径映射，不得填写具体覆盖率百分比。
- 未实际运行新的测试命令：执行结果只能引用 v28 验证报告中的 `mvn clean test` 944 通过、0 失败，不得虚构新时间、新总数或新覆盖率。
- API Key 信息：所有文档只能写环境变量名 `DEEPSEEK_API_KEY`，不得出现真实密钥、伪造密钥或可误用的示例密钥。

## 行为契约

- 本轮只交付 Markdown 文档，不新增业务功能、不修改服务公开契约、不新增测试类。
- 新增文档必须能作为课程实验 1 附件使用，覆盖测试计划、白盒测试用例、JUnit 执行结果、覆盖证据、缺陷修复与回归记录、结果分析和集成测试边界。
- `docs/test-plan.md` 必须说明测试目标、测试范围、测试环境、测试工具、测试分层和测试策略。
- `docs/test-cases.md` 必须覆盖 8 个核心功能，并体现成功路径、典型失败路径、边界输入和状态变化。
- `docs/coverage/README.md` 必须至少选择 3 个复杂核心方法，给出文字化控制流、圈复杂度、独立路径和测试用例映射。

- 所有文档中的命令默认从 `java-ai-assistant/` 目录执行。
- 文档不得声称普通 JUnit 测试访问真实 DeepSeek、真实网络、真实 API Key、真实用户文件或真实当前时间。
