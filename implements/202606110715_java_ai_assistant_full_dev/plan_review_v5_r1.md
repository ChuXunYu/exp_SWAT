# 计划审查报告（v5 r1）

## 审查结果
REJECTED

## 发现
- **[一般]** — `task_v5.md` 未把技术方案中 `MoneyValue` “统一按两位小数展示”的要求写入本轮任务约束。当前任务只要求 `MoneyValue` 使用 `BigDecimal`、允许 0 和负数、支持加减，后续详细设计和编码可能只实现算术包装，而没有稳定规范 `0`、`1.2`、`-3.4` 等统计金额的两位小数表达。收支统计、汇总和控制台展示都依赖该值对象提供一致金额语义；若本轮不明确，后续模块容易重复格式化或出现测试断言不稳定。

## 修改要求（仅 REJECTED 时）
- 对 `MoneyValue` 补充明确的两位小数展示/规范化要求：问题是当前任务遗漏了技术方案中的“两位小数展示”约束；这是问题，因为 `MoneyValue` 是后续收入总额、支出总额和结余统计结果的基础值对象，展示和断言如果不统一，会把金额格式规则泄漏到 finance、summary 或 console 层；期望修正方向是在 `task_v5.md` 中显式要求 `MoneyValue` 对外提供稳定的两位小数金额表达，并要求测试覆盖零值、正数、负数、尾随零和加减结果的两位小数行为。具体 API 名称和是构造期规范化还是提供格式化方法，可交由详细设计阶段决定。
