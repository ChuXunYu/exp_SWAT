# 计划审查报告（v8 r1）

## 审查结果
REJECTED

## 发现

- **[一般]** — `task_v8.md` 要求仓储列表查询返回“不可修改快照”，并要求服务“对外返回任务列表时应避免暴露可修改内部集合”，但没有明确查询结果中的 `TaskItem` 本身也不能作为仓储内可变实体直接暴露。当前 `TaskItem` 是可变实体，公开了 `updateDetails(...)`、`markCompleted()`、`reopen()` 等状态修改方法；如果 `TaskService.find/list/query` 直接返回仓储中的实体引用，即使外层集合不可修改，控制台层、汇总层、AI 草稿导入或测试调用方仍可绕过 `TaskService` 修改任务状态和基础信息。这与技术方案中“实体集合对外返回不可修改快照，避免控制台层或汇总层绕过服务修改内部状态”以及“汇总服务只读调用任务查询，不接收任务仓储引用”的边界目标不一致，会误导后续设计与实现。

## 修改要求（仅 REJECTED 时）

- 对“服务和仓储返回结果”的只读边界作出明确要求：`TaskService` 的查看、列表和组合筛选结果不得把仓储内部的可变 `TaskItem` 实例直接暴露给外部调用方。Planner 应在任务指令中指定一种稳定修正方向，例如新增只读 DTO/record（如 `TaskView`/`TaskSnapshot`）作为服务查询载荷，或要求仓储/服务返回防御性复制且复制对象的可变性不会影响仓储内部状态；同时补充测试要求，验证外部拿到查询结果后无法通过修改返回对象改变仓储内任务状态或基础信息。若选择 DTO，应同步更新预期文件列表和服务方法载荷语义；若选择复制，应明确复制规则和状态迁移副作用隔离规则。
