# 计划审查报告（v15 r1）

## 审查结果
REJECTED

## 发现

- **[一般]** — `NoteSearchPolicy` 的关键字大小写匹配语义没有被固定为强制契约。任务文件写明“关键字匹配标题和内容建议采用大小写不敏感包含匹配（`Locale.ROOT`）”，但测试要求覆盖“大小写”。在这种表述下，后续 Designer/Coder 可以选择大小写敏感或不敏感实现，Verifier 又可能按另一种预期编写测试，导致公开行为和测试断言分叉。关键字查询是笔记模块后续 `NoteQuery` / `NoteService` 的核心依赖，应在领域策略阶段固定唯一语义。

- **[一般]** — 标签替换操作的原子性未明确。任务已经要求 `updateContent(...)` 非法输入必须保持原状态不变，但对“替换全部标签”只要求拒绝空标签参数，没有说明当输入集合中包含 `null` 或非法标签时是否必须保持原标签集合不变。如果后续实现先清空内部标签再逐个校验/添加，失败路径会污染实体状态，影响后续仓储快照、标签查询和标签分布统计。

## 修改要求

1. 将 `NoteSearchPolicy` 的大小写规则从“建议”改为强制契约，例如明确标题和内容关键字匹配必须使用 `Locale.ROOT` 大小写不敏感包含匹配；标签匹配必须通过 `Tag.of(keyword)` 与标签集合做归一语义下的精确匹配。同步要求测试断言该唯一行为。

2. 明确 `Note` 的标签替换接口必须先完整校验输入集合引用、元素非空和标签有效性，再替换内部状态；任何非法输入都必须保持原标签集合不变。测试需覆盖替换标签失败后的状态不变性。
